## 1. HTML, CSS, JavaScript и Bootstrap

HTML задаёт содержание и смысл: заголовок, абзац, изображение, меню, форма. CSS отвечает за оформление: цвет, размер, расположение, отступы. JavaScript реагирует на события и меняет состояние: например, раскрывает меню при нажатии.

Bootstrap — библиотека готовых CSS-классов и JavaScript-компонентов. Браузер не знает слово `container` как специальную HTML-команду. Он видит обычный атрибут `class`, затем находит правило `.container` в подключённом CSS и применяет его. Если Bootstrap CSS не загрузится, надпись `class="container"` останется в HTML, но соответствующей раскладки не будет.

```html
<p class="text-center fw-bold">Lido Grocery Store</p>
```

`p` означает абзац. `class` содержит два отдельных класса через пробел. `text-center` центрирует текст, `fw-bold` делает его жирным. Ни один из классов не меняет абзац в заголовок: семантика остаётся у HTML-тега.

В CSS класс записывается с точкой: `.text-center`. В HTML внутри `class` точку не пишут. `class=".text-center"` создаст другое имя класса, которого в Bootstrap нет.

`id` обозначает конкретный элемент и должен быть уникальным в документе. Один и тот же класс может быть у многих элементов. Селектор `.site-header` ищет класс, а `#page-title` — id. В `href="#page-title"` символ `#` задаёт переход к элементу страницы с таким id. Один id может повторяться на разных HTML-страницах: это разные документы.

Bootstrap не создаёт сервер магазина. Кнопки не начинают принимать заказы только потому, что стали зелёными. В нашей работе Bootstrap оформляет форму, а отправка отключена, поскольку сервиса обработки нет.

**Наша архитектура:** обычные HTML-файлы → Bootstrap CSS через CDN → короткий личный CSS → Bootstrap bundle для меню. Никаких npm-сборок, React, собственного JS или базы данных для этого задания не нужно.

Источник для подключения: [Bootstrap Introduction](https://getbootstrap.com/docs/5.3/getting-started/introduction/).

## 2. Как подключение превращается в работающую страницу

В начале файла `<!DOCTYPE html>` включает современный стандартный режим HTML. Это не обычный тег с закрывающей парой. `<html lang="en">` сообщает основной язык содержимого; наша страница англоязычная, даже если мы обсуждаем её по-русски.

`<head>` содержит настройки документа, а `<body>` — содержимое страницы. `title` виден во вкладке браузера; `h1` — в самой странице. Они могут иметь разные формулировки.

`<meta charset="UTF-8">` задаёт кодировку: она нужна в том числе для символа ₸, типографских кавычек и кириллических имён файлов. `description` и `author` описывают документ, но не строят его сетку.

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

Мобильный браузер должен использовать ширину устройства в CSS-пикселях, а не широкую виртуальную страницу с последующим уменьшением. `initial-scale=1.0` задаёт начальный масштаб. Это не фиксирует ширину на 375 px: 375 — выбранная ширина проверки. CSS-пиксель не обязательно равен одному физическому пикселю дисплея.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css">
<link rel="stylesheet" href="css/temirlan.css">
```

Первая строка подключает Bootstrap, вторая — наш correction layer. Это укороченный учебный пример; в реальном файле есть ещё атрибуты integrity и crossorigin.

CDN — сеть, с которой браузер получает библиотеку. `@5.3.8` фиксирует версию; `min.css` — сжатый файл CSS, в котором убраны лишние пробелы. Сжатие не превращает CSS в другую технологию. Отдельный CSS-файл сайта остаётся обычным читаемым файлом.

`integrity` содержит контрольную сумму ожидаемого ресурса. Если содержимое не соответствует ей, браузер может заблокировать ресурс. При обновлении версии Bootstrap нужно обновлять и контрольную сумму. `crossorigin="anonymous"` задаёт режим запроса к другому origin без пользовательских cross-origin credentials; это связано с проверкой внешнего ресурса, а не со стилем кнопки.

В конце `body` загружается `bootstrap.bundle.min.js`. Он включает Bootstrap JavaScript и Popper. Для нашей сетки JS не нужен; для toggler нужен компонент Collapse. Подключение готового bundle не означает, что мы написали собственный JS. Bootstrap 5 также не требует jQuery.

Проверь мысленно: если отключить CSS Bootstrap, пропадёт его оформление; если отключить только JS bundle, сетка останется, но переключение закрытого меню по кнопке работать не будет. Если отключить интернет, файл страницы всё ещё откроется, но библиотека с CDN может не загрузиться, если её нет в кэше.

## 3. Почему CSS после Bootstrap не всегда побеждает

Каскад — способ выбора правила, когда на одно свойство одного элемента претендуют разные объявления. В упрощённом случае обычных авторских правил без слоёв и important сравниваются специфичность и затем порядок в CSS.

```css
.title { color: green; }
h1 { color: black; }
```

Если у `h1` есть класс `title`, зелёный цвет останется: селектор класса специфичнее селектора тега. Вторая строка находится ниже, но это не даёт ей автоматическую победу. Для равной специфичности и других равных условий выигрывает более позднее объявление.

У `.site-header h1` специфичность выше, чем у `h1`: первый селектор требует и класс предка, и тег. Поэтому общий зелёный заголовок у нас становится белым внутри зелёной шапки.

Многие Bootstrap utility-классы внутри самой библиотеки используют `!important`. Например, обычное позднее правило может не перебить цвет, заданный соответствующей utility. Запрет задания относится к нашему авторскому коду: нельзя писать своё `!important`, чтобы бороться с Bootstrap. Встроенный Bootstrap CSS мы не редактируем.

Наследование — другой механизм. `color` обычно наследуется потомками от родителя; `margin`, `padding`, `border` обычно не наследуются. Белый текст шапки может наследоваться абзацем, но отдельное правило заголовка может задать другой цвет. Поэтому нужно смотреть computed styles конкретного элемента.

Ещё ловушка: порядок классов в `class="mb-4 mb-0"` не задаёт приоритет. Перестановка слов не меняет порядок правил в CSS. Не оставляй две конфликтующие utility одного типа на одном breakpoint: выбери нужную. А сочетание `text-center text-md-start` осмысленно: оно задаёт разные режимы для разных ширин.

Correction layer означает, что библиотека делает основную работу, а наш CSS добавляет небольшие фирменные детали. В `temirlan.css` только цвета. Если снова написать там свою трёхколоночную сетку, красивый результат не отменит нарушения задания.

Для повторения каскада: [MDN Handling conflicts](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Handling_conflicts).

## 4. Box model и единицы измерения

У блока есть содержимое, внутренний отступ `padding`, рамка `border` и внешний отступ `margin`. Padding увеличивает пространство между текстом и рамкой; margin раздвигает соседние блоки снаружи. Фон элемента закрашивает content и padding, но не margin.

При обычном `content-box` заданная ширина относится к содержимому, поэтому padding и border добавляются сверху. При `border-box` ширина включает содержимое, padding и border; внешний margin всё равно остаётся отдельно. Bootstrap задаёт border-box через базовые правила, что помогает предсказуемо рассчитывать ширины.

`px` — CSS-пиксель. `%` — доля соответствующего размера содержащего блока. `rem` зависит от размера шрифта корневого `html`, а `em` зависит от контекста шрифта элемента. При стандартном корневом размере 16 px один rem равен 16 px, но пользователь или CSS может это изменить. Поэтому «p-3 всегда 16 пикселей» — недостаточно точный ответ: по умолчанию это 1 rem.

Если картинка шириной 800 px стоит в колонке 350 px и не умеет сжиматься, она может выйти за границы. `img-fluid` ограничивает максимальную ширину изображения размером родителя и сохраняет пропорции за счёт автоматической высоты. `width="400"` в HTML задаёт исходную размерную подсказку, а CSS может ограничить реальный размер. `img-fluid` не увеличивает маленькую картинку до полной ширины автоматически.

Почему нельзя просто скрыть горизонтальную прокрутку? `overflow-x: hidden` может замаскировать выходящий контент, а не исправить причину. Лучше найти слишком широкое изображение, поле, строку без переносов или неправильно вложенную row.

## 5. Контейнеры: где начинается макет

Обычная структура:

```html
<div class="container">
  <div class="row">
    <div class="col-12">Содержимое</div>
  </div>
</div>
```

Контейнер задаёт ширину области и боковые отступы. Row организует колонки. Column задаёт долю строки. Это разные обязанности; их не стоит объяснять одним словом «контейнер».

`.container` растёт ступенчато: занимает доступную ширину на узком экране и получает ограничение max-width на больших. `.container-fluid` занимает 100% доступной ширины родителя на всех размерах. Если поместить container-fluid внутрь узкого блока, он не прорвётся на весь экран: «100%» относится к его содержащему блоку.

| Ширина viewport | Максимальная ширина обычного container |
| --- | --- |
| Меньше 576 px | 100% доступной ширины |
| От 576 px | 540 px |
| От 768 px | 720 px |
| От 992 px | 960 px |
| От 1200 px | 1140 px |
| От 1400 px | 1320 px |

Это внешняя ширина контейнера в стандартной конфигурации; пространство для текста меньше из-за padding. На 1366 px наш основной container имеет max-width 1140 px, а не 1366. Поэтому чтение не растягивается на всю ширину экрана.

Есть responsive-контейнеры: `container-md` занимает доступную ширину до md, а с md использует соответствующие ограничения. Это полезный вариант, хотя для нашего задания достаточно обычного container и fluid.

У нас шапка и внешний подвал используют fluid для цветной полосы, а main — container для удобного чтения. Внутри широкого подвала есть обычный container: фон идёт широко, а контакты выравниваются с основным содержимым. Именно это объясняют комментарии в HTML.

Источник значений: [Bootstrap Containers](https://getbootstrap.com/docs/5.3/layout/containers/).

## 6. Breakpoints и mobile first

Breakpoint — порог ширины viewport, при котором начинают действовать определённые правила. Это не определение модели телефона и не проверка операционной системы. Узкое окно на компьютере может получить тот же режим, что телефон.

| Имя | От какой ширины | Пример |
| --- | --- | --- |
| xs | 0 | `col-12`, без `xs` в имени |
| sm | 576 px | `col-sm-6` |
| md | 768 px | `col-md-6` |
| lg | 992 px | `col-lg-4` |
| xl | 1200 px | `col-xl-3` |
| xxl | 1400 px | `col-xxl-2` |

Mobile first: сначала задаётся поведение для маленького экрана; правила с breakpoint меняют его начиная с указанного порога. `md` не означает «только на планшете». Правило продолжает действовать и выше, пока другой подходящий класс не задаст иное значение.

```html
<div class="col-12 col-md-6 col-lg-4">Карточка</div>
```

В проекте галерея товаров и обычные поля формы используют эту комбинацию. На 767 px применяется базовая полная ширина. На 768 px включается половина. На 991 px ещё половина. На 992 px включается треть. На 1366 и 1600 px остаётся треть, поскольку xl/xxl для этой колонки мы не задавали.

Класс без breakpoint не значит «работает только на телефоне». Он задаёт базовое правило для всех размеров; его конкретное свойство может быть переопределено responsive-правилом. Например, `mb-4` работает и на компьютере, если нет другого класса, который меняет тот же margin.

Источник порогов: [Bootstrap Breakpoints](https://getbootstrap.com/docs/5.3/layout/breakpoints/).

## 7. Сетка из 12 частей

Число в `col-4` означает четыре доли из двенадцати, а не четыре карточки. Ширина такой колонки — примерно 33.33% строки. Поэтому три одинаковые col-4 помещаются в один ряд. Для двух элементов берём col-6, для четырёх — col-3, для шести — col-2.

```text
col-12: [                12                ]
col-6:  [        6        ][        6        ]
col-4:  [     4     ][     4     ][     4     ]
col-3:  [   3   ][   3   ][   3   ][   3   ]
```

Двенадцать — удобная система долей, а не требование поставить ровно двенадцать HTML-элементов. Комбинация 4 + 8 заполняет строку, 3 + 6 оставляет место, а 8 + 6 превышает доступное место: следующая колонка переносится. Это поведение переноса, а не автоматическая ошибка HTML.

`.row` в стандартной сетке Bootstrap реализована через Flexbox с переносом. Название «grid system» не означает, что `.row` использует CSS `display: grid`. Запрет задания на собственные flex/grid-раскладки не запрещает применять готовую сетку Bootstrap, внутри которой используется Flexbox.

Разница вариантов:

- `col-6`: заданная половина во всех размерах.
- `col`: гибкое равное распределение доступного места между такими колонками.
- `col-auto`: размер по содержимому, а не заданная доля 12.
- `row-cols-3` на row: задаёт число колонок детям; это другая схема, её число означает количество элементов в ряду.
- `offset-md-2`: добавляет смещение на две доли с md; не надо им исправлять случайные ошибки отступов.
- `order-md-2`: меняет визуальный порядок с md. Порядок исходного HTML и чтения вспомогательными технологиями от этого автоматически не становится таким же.

### Почему column обычно должна быть прямым ребёнком row

Row управляет своими flex-элементами — непосредственными детьми. Если вставить лишнюю обёртку между row и всеми колонками, эта обёртка станет единственным flex-элементом, и нужные колонки могут перестать формировать ожидаемый ряд. У нас обёртка `.col-*` находится снаружи product-card, поэтому сетка задаёт ширину карточке через колонку.

### Nested row

```html
<div class="row">
  <div class="col-12 col-lg-8">
    <div class="row g-3">
      <div class="col-6">A</div>
      <div class="col-6">B</div>
    </div>
  </div>
</div>
```

Внутренняя сетка снова делится на 12, но уже относительно ширины внешней колонки. На lg внешняя часть занимает 8/12 строки, а каждый внутренний блок — 6/12 от неё. Приблизительная доля относительно внешней строки: 8/12 × 6/12 = 1/3; реальные размеры содержимого ещё учитывают gutters.

В нашей форме вложенность: `form.row` → `fieldset.col-12` → внутренняя `div.row.g-3` → абзацы с `col-*`. У fieldset есть смысл: он объединяет поля, а legend называет группу. Column не обязана быть именно div; важно, чтобы HTML-вложенность оставалась допустимой.

Источник системы: [Bootstrap Grid](https://getbootstrap.com/docs/5.3/layout/grid/).

## 8. Gutters, padding, margin и gap

Gutters — промежутки сетки между колонками. В Bootstrap они связаны с padding колонок и компенсирующими отрицательными margin строки. Поэтому row следует помещать в предусмотренный контейнер/колонку: случайная row у самого края документа может выйти за границы.

`g-3` задаёт горизонтальные и вертикальные gutters; `gx-3` только горизонтальные, `gy-3` только вертикальные. `g-0` убирает оба. Размер по умолчанию у `.row` без g-класса — горизонтальный gutter 1.5 rem и нулевой вертикальный; у `g-3` обе оси получают 1 rem. То есть g-3 не «добавляет три пикселя».

Шкала Bootstrap по умолчанию:

| Суффикс | Размер | При корневом шрифте 16 px |
| --- | --- | --- |
| 0 | 0 | 0 px |
| 1 | 0.25 rem | 4 px |
| 2 | 0.5 rem | 8 px |
| 3 | 1 rem | 16 px |
| 4 | 1.5 rem | 24 px |
| 5 | 3 rem | 48 px |

Синтаксис отступа: свойство + сторона + необязательный breakpoint + размер. `m` — margin, `p` — padding; `t` — верх, `b` — низ, `s` — начало строки, `e` — конец, `x` — обе горизонтальные стороны, `y` — обе вертикальные. Без стороны применяются все четыре.

В англоязычной странице start — слева, end — справа. Логические start/end удобнее left/right при поддержке языков с другим направлением письма.

Расшифровка:

- `py-4`: по 1.5 rem внутреннего отступа сверху и снизу.
- `mb-4`: внешний отступ снизу 1.5 rem.
- `ps-3`: внутренний отступ со стороны начала 1 rem.
- `mx-auto`: автоматические внешние отступы по горизонтали; их эффект зависит от доступного места и типа раскладки.
- `mt-md-5`: с 768 px верхний margin становится 3 rem; ниже этого класса нет.
- `gap-2`: промежуток между элементами flex/grid-контейнера 0.5 rem. Сам по себе он не включает flex.

В нашей группе кнопок `d-flex flex-wrap gap-2` сначала включает flex-контейнер, затем разрешает перенос и задаёт промежутки. Это стандартные utilities Bootstrap. В личном CSS мы не пишем собственный `display: flex` для этого блока.

Если увеличить gutters при уже тесном контейнере, проверяй переполнение. Не добавляй произвольный `gap` к колонкам с фиксированными долями 6/12 + 6/12: сумма ширин уже занимает строку, дополнительный gap может переносить вторую колонку. Для стандартной Bootstrap-сетки используй g/gx/gy.

Источники: [Gutters](https://getbootstrap.com/docs/5.3/layout/gutters/), [Spacing](https://getbootstrap.com/docs/5.3/utilities/spacing/).

## 9. Display, Flexbox и выравнивание

`display` определяет поведение блока в раскладке. `block` обычно начинает новую строку; `inline` участвует в текстовой строке; `inline-block` остаётся в строке, но позволяет управлять размером как блоком. `none` исключает элемент из раскладки. `flex` превращает элемент в flex-контейнер, который управляет непосредственными детьми.

```html
<a class="d-none d-md-inline-block" href="#page-title">Top</a>
```

Ниже 768 px ссылка не занимает места. С 768 px она видима как inline-block. Это не удаляет элемент из HTML и не удаляет его href: меняется display. Если убрать d-md-inline-block, останется d-none на всех ширинах.

Для показа только в диапазоне md можно написать `d-none d-md-block d-lg-none`: скрыто до 768, видно от 768 до ширины меньше 992, затем снова скрыто. `invisible` действует иначе: скрывает видимость, но место в макете сохраняется. `visually-hidden` предназначен для визуально скрытого текста, который должен оставаться доступным вспомогательным технологиям.

`text-center text-md-start` центрирует текст на маленькой ширине и выравнивает его по началу строки с md. Это не универсальный способ центрировать сам блочный элемент. Чтобы центрировать блок ограниченной ширины, могут понадобиться margin auto или выравнивание родителя. Чтобы центрировать flex-детей, используются другие свойства.

У Flexbox две оси: главная и поперечная. При `flex-row` главная горизонтальная, при `flex-column` вертикальная. `justify-content-center` выравнивает по главной оси; `align-items-center` — по поперечной. Поэтому утверждение «justify всегда по горизонтали» неверно. `flex-wrap` разрешает перенос, `flex-nowrap` запрещает.

У нас `align-items-center` на строке с фото выравнивает изображение и текст по поперечной оси. На широком экране они стоят рядом и выглядят вертикально согласованными. Класс не означает, что текст стал выровнен по центру внутри абзаца.

`gap-lg-3` в navbar начинает задавать gap с 992 px. До lg ссылки идут в раскрываемом мобильном меню; на lg и выше появляются промежутки между элементами горизонтального меню.

Источники: [Display](https://getbootstrap.com/docs/5.3/utilities/display/), [Flex](https://getbootstrap.com/docs/5.3/utilities/flex/), [Text](https://getbootstrap.com/docs/5.3/utilities/text/).

## 10. Typography, цвета, границы и тени

HTML-заголовки h1-h6 обозначают уровни структуры документа. Классы `.h1`-`.h6` дают похожее визуальное оформление без изменения семантики тега. У нас `<h2 class="h3">` остаётся заголовком второго уровня, но получает визуальный размер h3. Это нормальный способ отдельно управлять смыслом и видом.

`display-5` — выразительный крупный заголовок; `lead` — выделенный вводный текст; `fw-bold` — жирный вес; `small` — уменьшенный текст. Тег `<small>` несёт семантику небольшого примечания, а класс `.small` — в первую очередь визуальный размер. `text-body-secondary` задаёт вторичный цвет текста с учётом темы Bootstrap.

Номер display — имя варианта, а не число пикселей и не уровень h5. Размеры Bootstrap могут адаптироваться через механизм responsive font sizes. Поэтому нельзя обещать один фиксированный пиксельный размер display-5 на всех экранах.

`text-warning` меняет цвет текста. `bg-white` меняет фон, но не обязательно цвет текста. `text-bg-warning` совместно задаёт фон и подходящий текстовый цвет для контекстного варианта. Нельзя полагаться только на цвет для передачи смысла: у Popular есть и текстовая метка.

`border` добавляет рамку; `border-bottom` задаёт нижнюю сторону; `border-start` — начальную сторону; `border-success` меняет цвет рамки; `border-4` — её толщину. Если на одном блоке есть border-bottom и border-start, цвет и толщина могут повлиять на обе существующие стороны. Именно поэтому у Product Information заметны и левая, и нижняя зелёные линии. Это реальное следствие набора классов, а не отдельный нарисованный элемент.

`rounded` скругляет углы; `shadow-sm` добавляет небольшую тень. Это utilities, не компоненты. `h-100` задаёт высоту 100% относительно содержащего блока при подходящем контексте размеров. В нашей сетке растянутые колонки и h-100 помогают карточкам одного ряда иметь равную высоту. Это не обещание равной высоты всех карточек во всех разных рядах.

`text-break` помогает разрывать длинный текст вроде email, чтобы тот не выходил за доступную ширину. Это одна из мер против переполнения, но не замена правильной сетке.

`img-fluid` ограничивает изображение; `figure`, `figure-img` и `figure-caption` дают согласованное оформление изображения и подписи. Изображения у нас разного соотношения сторон, поэтому их видимые высоты различаются. Мы не обрезали фотографии ради одинаковых прямоугольников.

Источники: [Typography](https://getbootstrap.com/docs/5.3/content/typography/), [Images](https://getbootstrap.com/docs/5.3/content/images/), [Borders](https://getbootstrap.com/docs/5.3/utilities/borders/).

## 11. Navbar и Collapse: механизм целиком

У меню есть три части: внешняя навигация, кнопка переключения и раскрываемый блок со ссылками. Кнопка должна знать, какой блок переключать. Раскрываемый блок должен иметь соответствующий id. CSS задаёт внешний вид и режимы ширины, а bundle обрабатывает клик.

```html
<nav class="navbar navbar-expand-lg" data-bs-theme="dark">
  <div class="container">
    <button class="navbar-toggler" type="button"
            data-bs-toggle="collapse" data-bs-target="#main-navigation"
            aria-controls="main-navigation" aria-expanded="false"
            aria-label="Toggle navigation">
      <span class="navbar-toggler-icon"></span>
    </button>
    <div class="collapse navbar-collapse" id="main-navigation">
      <ul class="navbar-nav">
        <li class="nav-item">
          <a class="nav-link active" href="index.html" aria-current="page">Home</a>
        </li>
      </ul>
    </div>
  </div>
</nav>
```

Разбери каждую связь:

1. `nav` — семантическая область навигации. `aria-label` в нашем полном файле уточняет её назначение.
2. `navbar` даёт базовое оформление компонента. Сам по себе наш `site-nav` — пользовательское имя для фирменного фона.
3. `navbar-expand-lg` включает постоянно раскрытый вид с lg, то есть от 992 px. Ниже показывается toggler, и меню управляется Collapse. На планшете 768 px у нас тоже toggler; это намеренный выбор.
4. `data-bs-theme="dark"` выбирает тёмную тему Bootstrap для содержимого navbar. Фактический тёмно-зелёный фон задан correction layer. Атрибут темы не означает автоматическое создание именно нашего цвета фона.
5. `type="button"` делает кнопку обычной кнопкой действия; она не должна случайно отправлять форму.
6. `data-bs-toggle="collapse"` сообщает Bootstrap, какой механизм использовать.
7. `data-bs-target="#main-navigation"` содержит CSS-селектор целевого блока, поэтому тут есть #.
8. `aria-controls="main-navigation"` сообщает связь для вспомогательных технологий; здесь указывается id без #.
9. `aria-expanded="false"` задаёт исходное закрытое состояние. Bootstrap обновляет этот атрибут при переключении.
10. `aria-label` даёт кнопке понятное имя, хотя внутри нет слова Menu.
11. Пустой span с `navbar-toggler-icon` не бесполезный элемент ради utility: Bootstrap рисует на нём иконку переключателя.
12. `collapse navbar-collapse` обозначает управляемый блок меню. В открытом состоянии Bootstrap добавляет `.show`; во время перехода использует `.collapsing`.
13. `navbar-nav`, `nav-item`, `nav-link` оформляют список и ссылки. `active` — визуальное состояние, `aria-current="page"` — обозначение текущей страницы для доступности.

Если id и target отличаются хотя бы одним символом, кнопка не найдёт блок. Если продублировать id внутри одной страницы, выбор цели станет неправильным. Если нет bundle, атрибуты останутся данными в HTML без работающего обработчика.

Не говори, что `aria-expanded` само открывает меню: aria описывает состояние, а не реализует поведение. Не говори, что `.active` автоматически узнаёт текущую страницу: в наших статических файлах класс расставлен вручную.

Для проверки нажми toggler мышью, затем попробуй Tab и Enter/Space. Доступность проверяется не только наличием aria-атрибутов. Переключатель — настоящий button, поэтому браузер даёт ему стандартное управление с клавиатуры.

Источник и исходный образец: [Bootstrap Navbar](https://getbootstrap.com/docs/5.3/components/navbar/).

## 12. Кнопки и настоящие действия

`btn` — общая основа кнопки. `btn-success` — цветовой вариант, `btn-outline-success` — вариант с контуром. `btn-lg` и `btn-sm` меняют размер. Эти классы оформляют элемент, но не определяют его действие.

```html
<a class="btn btn-outline-success btn-sm" href="#page-title">Top</a>
<button class="btn btn-outline-success" type="reset">Reset</button>
<button class="btn btn-success btn-lg disabled" type="submit" disabled>Submit Request</button>
```

Первая строка — ссылка, которая прокручивает к заголовку. Вторая — кнопка сброса полей формы к исходным значениям. Третья — submit-кнопка в недоступном состоянии. Если убрать оформление btn, назначение href/type не исчезнет. Если оставить красивую кнопку без правильного href или type, действие само не появится.

`disabled` как HTML-атрибут у button отключает стандартное взаимодействие. `.disabled` — CSS-класс оформления. У `<a>` нет работающего нативного disabled-атрибута: одна надпись disabled не превращает ссылку в недоступную кнопку. Для недоступной ссылки нужны другие меры; в нашем задании проще корректно показать disabled на настоящем button.

Ловушка булевых атрибутов: `disabled="false"` всё равно означает наличие disabled. Чтобы включить кнопку, атрибут нужно удалить, а не написать false строкой. Аналогично устроен `required`.

У нашей Submit Request одновременно есть disabled-атрибут, disabled-класс и `aria-describedby="request-status"`, связывающий кнопку с поясняющим абзацем. Это осмысленное недоступное действие: в статическом сайте нет сервиса приёма запросов. Reset остаётся работающей кнопкой. Не обещай преподавателю, что магазин получит письмо после отправки формы.

Источник: [Bootstrap Buttons](https://getbootstrap.com/docs/5.3/components/buttons/).

## 13. Формы: HTML отвечает за данные, Bootstrap за вид

`form` объединяет элементы ввода. `action` задаёт адрес отправки, `method` — способ. У нас исторически стоит `action="products.html" method="get"`. Если бы отправка была включена, браузер мог бы переходить на этот адрес с параметрами в query string. Это не база данных и не обработчик заказа. В текущей версии submit отключён.

`id` нужен для уникального обращения к полю и связи с label; `name` определяет имя параметра при отправке. Их можно сделать одинаковыми, но назначение разное. Поле с id, но без name, обычно не попадёт в отправляемые данные формы как именованный параметр.

```html
<label class="form-label" for="customer-email">Email:</label>
<input class="form-control" type="email" id="customer-email"
       name="customer-email" placeholder="Enter your email" required>
```

`for` должен совпасть с id поля. Это позволяет кликнуть по подписи для фокуса и помогает озвучить назначение поля. Placeholder — временная подсказка внутри; он исчезает при вводе и не заменяет постоянный label.

`type="email"` включает базовую браузерную проверку формата, но не проверяет существование почтового ящика. `type="tel"` может подобрать удобную клавиатуру на телефоне, но сам по себе не задаёт строгий формат номера. `type="number" min="1"` задаёт числовой ввод и нижнюю границу. `type="date"` даёт браузерный интерфейс выбора даты, вид которого зависит от браузера и ОС.

`required` говорит, что обязательное поле нужно заполнить для обычной отправки. Это клиентская проверка, которую нельзя считать защитой настоящего сервера. В реальном приложении сервер должен проверить полученные данные заново. Для нашего статического учебного сайта серверная часть не создавалась.

`select` содержит варианты option. Текст option виден человеку, а value — значение для отправки. У radio одна группа определяется одинаковым name: в группе можно выбрать один вариант. У нас `contact-method` общий для email и phone. Checkbox независим и удобен для согласия. Required у согласия означает, что при обычной отправке его нужно отметить.

`textarea` — многострочное поле. `rows` задаёт подсказку по высоте в строках, `cols` — размер в символах при стандартном отображении. Класс form-control задаёт ширину через CSS, поэтому cols не должен восприниматься как запрет адаптивного сжатия.

`fieldset` объединяет связанные поля, `legend` даёт группе заголовок. Форма и fieldset могут одновременно участвовать в сетке. Добавление Bootstrap-класса не отменяет их HTML-смысл.

Form-классы: `form-control` для текстовых полей и textarea; `form-select` для списка; `form-label` для подписи; `form-check-input` и `form-check-label` для radio/checkbox. Пара `form-control` и `col-*` обычно распределена между полем и внешней колонкой, чтобы оформление поля не смешивалось с шириной блока сетки.

Источник: [Bootstrap Forms](https://getbootstrap.com/docs/5.3/forms/overview/).

## 14. Компонент, utility и пользовательский класс

Utility решает одну небольшую задачу: padding, цвет, display, тень. Component — согласованный набор элементов и классов для целой части интерфейса, например navbar или card. Пользовательский класс — имя, которое определили мы; оно работает только если на него есть правило или другая логика.

В `class="product-card card h-100 shadow-sm"`:

- `product-card` — сохранённое смысловое имя блока. В новом correction layer отдельного правила для него нет.
- `card` — компонент Bootstrap.
- `h-100` — utility высоты.
- `shadow-sm` — utility тени.

Не каждый класс из исходного проекта обязан иметь активное правило CSS. `content-section`, `about-section`, `page-home`, `request-form` помогают узнавать части документа, но сами по себе не создают автоматических эффектов. Проверяй stylesheet, прежде чем приписывать классу действие.

У карточки `.card` задаёт внешнюю оболочку, `.card-body` — внутреннюю область с отступами, `.card-title` — оформление заголовка. У нас внутри оставлены существующие h3, figure, img и figcaption. Мы адаптировали компонент к содержимому, а не заменили сайт готовым шаблоном.

Card не требует JavaScript. Badge тоже может быть чисто визуальным компонентом. Accordion, modal, collapse и carousel обычно используют JavaScript для интерактивного поведения. Не нужно подключать собственный обработчик только потому, что выбран компонент.

Комментарий над галереей называет компонент и объясняет адаптацию. Popular раньше появлялся через CSS-псевдоэлемент; теперь это настоящий текстовый badge. Он участвует в нормальном потоке и не перекрывает заголовок абсолютным позиционированием.

Источник: [Bootstrap Cards](https://getbootstrap.com/docs/5.3/components/card/).

## 15. HTML-смысл наших страниц

`header` — вводная часть; `nav` — навигация; `main` — основное содержимое; `section` — тематический раздел, обычно с заголовком; `article` — самостоятельный материал, у нас карточка категории; `aside` — дополнительная информация; `footer` — завершающая информация и контакты. Div — нейтральный контейнер без такого специального смысла.

Span — нейтральный строчный элемент. В Home внутри абзаца с row используются span с колонками: это допустимое текстовое содержимое p. Нельзя просто заменить их div внутри p: блочный div не является допустимым содержимым абзаца, и браузер может автоматически закрыть p, изменив DOM. Bootstrap меняет CSS-раскладку, но не отменяет правила HTML-вложенности.

Список `ul` неупорядоченный; `ol` упорядоченный; элементы — li. Вложенный ul напитков находится внутри соответствующего li. `dl` — список терминов и описаний; `dt` — термин, `dd` — описание. Эти теги не являются колонками Bootstrap сами по себе, но могут получить col-классы.

`strong` подчёркивает важность, `em` — смысловое ударение; `b` и `i` имеют другие текстовые назначения и часто дают похожий вид. `mark` выделяет фрагмент, `sub` опускает индекс, поэтому H₂O — буква H, нижний индекс 2, буква O. `blockquote` задаёт отдельную цитату, `q` — короткую встроенную, `cite` используется для обозначения названия/ссылки на источник; наш исходный текст с именем и датой внутри cite сохранён, но строго семантически имя человека само по себе не является названием произведения.

`figure` группирует самостоятельную иллюстрацию с `figcaption`. `alt` — текстовая альтернатива картинки, не её подпись и не всплывающая подсказка. `src` — путь к изображению. Поскольку страницы и фотографии лежат рядом, используется относительный путь. Перемещение HTML в другую папку меняет базу для всех таких путей.

`href="tel:..."` предлагает открыть приложение звонка; `mailto:` — почтовое приложение. Это не автоматический звонок/отправка. `target="_blank"` открывает новый контекст, обычно вкладку; `rel="noopener noreferrer"` ограничивает связь с opener и передачу referrer для перехода. `&amp;` — HTML-запись амперсанда в тексте; браузер показывает `&`.

## 17. Как проверять и искать причину поломки

Открой файл в браузере. В инструментах разработчика включи режим изменения ширины. Проверь 375, 768 и desktop, а затем соседние значения 767/768 и 991/992. Смотри не только верх страницы: прокрути до длинных описаний, формы и email в подвале.

Если есть горизонтальная прокрутка, найди элемент, который выходит за правую границу. Проверь фиксированную ширину, содержимое без переносов, изображение без img-fluid, слишком большие отступы и row без подходящего родителя. Не добавляй отрицательные margin наугад.

Если классы «не работают», проверь Network: загрузился ли Bootstrap CSS, совпадает ли версия и integrity. Затем Elements → Styles/Computed: есть ли нужное правило, не зачёркнуто ли оно, активен ли breakpoint. У элемента может быть правильный класс, но viewport меньше порога.

Если не открывается меню: проверь bundle, одинаковые target/id, наличие collapse, ошибки в консоли, правильность data-bs-атрибутов. Не путай Bootstrap 4 `data-toggle` с Bootstrap 5 `data-bs-toggle`.

Валидатор HTML проверяет структуру и допустимость разметки. Ноль ошибок не доказывает отсутствие переполнения, загрузку CDN, контрастность, удобство клавиатуры или работоспособность ссылок. Поэтому отдельно нужны браузерные проверки. У наших двух страниц локальный Nu Checker дал ноль ошибок и предупреждений; это результат конкретных файлов, а не всех будущих правок.

При работе из локальных файлов сохраняй HTML и фотографии в прежних местах. PDF с GitHub-ссылкой показывает результат работы, но не заменяет исходники в репозитории. Интернет нужен для CDN, хотя сервер для запуска самого сайта не требуется.

## 19. Вопросы преподавателя и ответы с объяснением

**1. Что такое Bootstrap?** Готовые стили и интерактивные компоненты для интерфейса. Мы применяем классы к своему HTML. Библиотека ускоряет согласованную вёрстку, но не заменяет смысловую структуру документа и серверную логику.

**2. Почему не написать весь CSS самому?** В этом задании нужно показать использование готовой системы. Стандартные классы уже согласуют размеры, отступы и breakpoint-поведение; свой CSS нужен только для небольших особенностей бренда.

**3. Что означает число 6 в col-md-6?** Шесть долей из двенадцати, то есть половина строки, начиная с 768 px. Это не шесть карточек и не 6 px. Поведение ниже порога задают другие правила, у нас col-12.

**4. Почему col-md-6 работает на 1200 px?** Порог задаётся снизу. Если нет более подходящего переопределения, правило продолжает действовать выше. У наших карточек есть col-lg-4, поэтому конкретно у них на 1200 уже треть.

**5. Что изменится без col-lg-4?** При сохранении col-12 col-md-6 карточки будут полными до md и половинными начиная с md, в том числе на desktop. Удаление lg не возвращает базовый col-12 на больших экранах.

**6. Что произойдёт с тремя col-5?** Каждая занимает 5/12. Две занимают 10/12 и помещаются, третья переносится. Bootstrap не уменьшит каждую до одной трети только ради красивого ряда.

**7. Для чего row?** Это контейнер колонок со стандартным механизмом Flexbox, переносом и gutters. Он управляет прямыми детьми. Без row колонки могут иметь ширины, но не организоваться в нужную строку.

**8. Почему в документации написано grid, а в CSS flex?** Grid здесь — название системы колонок. Обычная Bootstrap grid реализована через Flexbox. У Bootstrap есть и отдельные возможности CSS Grid, но мы их не подключали.

**9. Зачем container, если уже есть row?** Container ограничивает ширину и задаёт боковые отступы; row группирует колонки. Один не полностью заменяет другого.

**10. Чем container-fluid отличается от container?** Fluid сохраняет 100% доступной ширины. Обычный container получает максимальную ширину по breakpoint. У нас первый нужен для широкой цветной шапки, второй — для удобного чтения основного текста.

**11. Почему внутренние col-6 не занимают половину экрана?** Их ширина считается от внутренней row. Если она находится внутри узкой внешней колонки, половина относится к этой области.

**12. Чем g-3 отличается от gap-3?** g-3 управляет gutters стандартной сетки Bootstrap. gap-3 задаёт CSS gap подходящему flex/grid-контейнеру. Они могут выглядеть похоже, но механизм и контекст применения различаются.

**13. Чем padding отличается от margin?** Padding находится внутри рамки элемента, margin — снаружи. Поэтому p-3 увеличивает внутреннее пространство карточки, а mb-3 раздвигает её с последующим элементом.

**14. Почему порядок файлов CSS важен?** Поздние объявления могут переопределять ранние при равных условиях каскада. Но позднее подключение не отменяет специфичность и important. У нас correction layer идёт после Bootstrap для осмысленных цветовых поправок.

**15. Есть ли у нас собственный JavaScript?** Нет. Подключён готовый Bootstrap bundle. Он обеспечивает меню. Мы не писали обработчики, скрипты формы или логику заказа.

**16. Почему меню не раскрывается одним CSS-классом?** Адаптивное расположение задаёт CSS, а переключение состояния по нажатию в выбранном компоненте обрабатывает JavaScript Bootstrap.

**17. Что будет без aria-expanded?** Компонент может визуально работать, но исходное состояние хуже описано для вспомогательных технологий. ARIA нужна для доступности и связи состояний, она не заменяет логику Collapse.

**18. Почему data-bs-target начинается с #, а aria-controls нет?** Первый содержит CSS-селектор; второй — значение id связанного элемента.

**19. Что делает active?** Выделяет текущий пункт визуально. В статических файлах мы сами ставим его на нужную ссылку. Для доступного обозначения текущей страницы добавляем aria-current.

**20. Чем h2 отличается от класса h2?** Тег задаёт уровень смысловой структуры. Класс задаёт внешний вид. У h2 с классом h3 уровень остаётся вторым.

**21. Можно ли сделать кнопку из div?** Визуально можно, но придётся вручную восстанавливать семантику, фокус и клавиатурное поведение. Для действия используй button, для перехода — a с href. В задании требуется реальная ссылка или form control.

**22. Почему submit отключён?** Это осмысленный disabled state: статический сайт не отправляет запрос магазину. Пользователь видит пояснение, может заполнить демонстрационные поля и сбросить их. Мы не выдаём оформление за работающий сервис.

**23. Почему disabled="false" не включает кнопку?** Это булев HTML-атрибут: само присутствие включает состояние. Для включения кнопки нужно удалить атрибут.

**24. Что делает required?** Включает браузерную обязательность поля при обычной отправке. Это не серверная валидация и не гарантия корректности всех возможных данных.

**25. Зачем одновременно id и name?** Id связывает конкретный элемент с label, якорями и селекторами. Name задаёт имя отправляемого параметра. Они не взаимозаменяемы.

**26. Что делает img-fluid?** Ограничивает картинку шириной родителя и сохраняет пропорции. Оно не превращает все изображения в одинаковые по высоте и не гарантирует увеличение маленькой картинки.

**27. Какие правила ты удалил?** Например, ручную product-gallery grid заменил на row/col; float фотографии на responsive-колонки; собственный flex кнопок — на d-flex/flex-wrap/gap utilities; ручное оформление кнопок — на btn-варианты. В остальных страницах общий старый CSS остаётся вне моей зоны работы.

**28. Зачем комментарии в HTML?** Они фиксируют версию Bootstrap, причину выбора контейнеров и адаптацию компонента. Браузер не показывает комментарии как обычный текст страницы.

**29. Что показывает ноль ошибок валидатора?** Проверяемые файлы соответствуют правилам HTML, которые проверяет этот инструмент. Это не полноценная проверка внешнего вида, интерактивности и удобства интерфейса.

**30. Что проверял на телефоне?** Ширину документа, отсутствие бокового переполнения, загрузку изображений, укладывание полей и контактов, закрытое и открытое меню. Проверял и tablet/desktop, а не только один удачный скриншот.

### Задание 1. Оставить две карточки и на desktop
